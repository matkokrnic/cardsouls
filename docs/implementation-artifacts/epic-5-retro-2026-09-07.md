## 2. The `E4-R` operational rules in practice

### 2.1 `LAYER-COMPLETION:` — the line held where a report survives, and 10 of 12 reports do not

Measured, whole-tree, case-insensitive: **the string appears in ZERO of the twelve E5 story files.**
It appears in exactly two artifacts, both out-of-repo:

- `C:\dev\_51a-review.md` — four lines, canonical form: Blind Hunter / Edge Case Hunter /
  Acceptance Auditor / RUN, each with a terminal state and a finding count. This is the rule working
  exactly as written.
- `C:\dev\_52-review.md` — eight lines, but naming *topics* (`preconditions`, `acceptance-audit`,
  `charge-reach latch`, `determinism/replay`, …), not the declared review layers. Greppable, and
  more informative than E4's silence — but it is not "each declared layer with its terminal state".

For the other ten stories **no review report artifact exists anywhere** — not in the repo, not in
`C:\dev`. `5-1`'s board note says "(review passed)" with only a gate file surviving.
`5-6-three-tier-ladder.md:971` cites `docs/implementation-artifacts/5-6-code-review.md` as the file
its fix pass was applied against; that path **has never existed in git history and is not on disk**.

**The honest reading is two-sided.** `E4-R/R2` put the line "in the story's review section", and no
E5 story file has a review section carrying it — a literal miss in 12 of 12. But the substance the
line was a proxy for got *better*: every E5 close-out session carries an explicit
"Accepted without change (review findings, no ruling needed)" block naming each finding
(`5-0b`, `5-0c`, `5-1`, `5-3`, `5-4`, `5-5`, `5-7/R7` itemises five). E4's finding B — 48 findings
recorded nowhere a future reader would look — **does not recur**; the findings are in the log. What
does not survive is the report that produced them, so the *terminal state of each layer* is
unauditable for ten stories. The rule's mechanism and the rule's purpose came apart.

**RATIFIED — `E5-R/R2`.** The report gets a durable artifact and the log gets the layer states.
The review report is **written with the Write tool to `C:\dev\_<story>-review.md`** so the artifact
survives the session that produced it; the story's **close-out log session carries ONE line naming
each declared layer with its terminal state**; and the browser still REJECTS a report that does not
carry its `LAYER-COMPLETION:` line. Two writes, no new check — priced against the meta-rule, this
costs one file path and one sentence per story.

## 9. Lessons carried forward

1. **A forcing point discharges a queue; a fence does not.** The arch amendment queue was opened,
   added to, refused a shortcut, and emptied — because `5-3/R4` named E5 close-out as the venue.
   E4's queue had no venue and leaked six stale claims. This is `E4-R/R1`'s rule generalised from
   decisions to debt. (`E5-R/R1`)
2. **An instrument aimed at less than the rule asks for reads as compliance.** `E4-R/R3` produced 41
   files where E4 produced one number — an unambiguous win — and every recorded delta stops at the
   dev pass, so `5-0d` reports "well inside" while the full interval is over budget. The correction
   is smaller than the last one: name which two files, not whether to measure. (`E5-R/R3`)
3. **Removing a capability beats widening a check.** `5-7/R8` answered a twice-broken read-only
   brief by deleting subagents from create and docs-only passes entirely. Costs the operator
   nothing to enforce, and is the only kind of process rule that has survived three epics here.
   (`E5-R/R6`)
4. **The gate is where scope gets cheap.** `5-2` spent sixteen rulings before any code, declined its
   own pre-named break, and shipped in one commit. E4 spent eleven docs-only gate rounds discovering
   the same thing by subtraction. `E4-R/R4`'s corollary — behaviour and acceptance, not mechanism —
   is what changed, and it changed the epic's whole commit shape. (`E5-R/R4`)
5. **Findings survived; reports did not.** Closing E4's leak by writing findings into the close-out
   session worked, and it quietly made the report disposable — ten are gone, one cited path never
   existed. What is lost is not the finding but the audit trail behind it. (`E5-R/R2`)
6. **A record can be true and still be wrong.** `5-0b`'s golden claim is right about the behaviour
   and two re-baselines stale on the hash. The suite would have caught a real drift; nothing catches
   a stale identifier in prose, and nothing needs to — but a reader trusting the number would be
   misled, which is the whole argument for the evidence audit being an acceptance criterion. The
   correction lives here and in the log, never in the pushed story. (`E5-R/R7`)
